# GRPO: Review after passing

- **Computing standard deviation across groups.** Changing another prompt's reward scale should not affect the current prompt. `test_group_advantage_invariants` modifies only the second group and requires the first to stay unchanged. [TRL v0.23.1](https://github.com/huggingface/trl/blob/v0.23.1/trl/trainer/grpo_trainer.py) uses `std(dim=1)`, corresponding to PyTorch's default correction of 1; the original exercise checked this on 2026-10-13. Epsilon is added outside the standard deviation. Exact invariance to positive reward scaling holds only when eps=0.
- **Padding contamination or NaNs.** Extreme probability differences at invalid tokens may overflow before multiplication by zero. `test_padding_isolation` checks ordinary values, a difference of two thousand at invalid positions, and zero gradients there.
- **A sometimes-negative k1 estimate.** A single sample of `log pi - log pi_ref` can be negative. This exercise specifies k3, which `test_k3_nonnegative` distinguishes. Its interpretation as KL still depends on the sampling distribution; it is not universally unbiased on off-policy batches. See [Schulman's original blog post](http://joschu.net/blog/kl-approx.html). That site returned an error during the original exercise's source check, so the formula was also checked against TRL v0.23.1 and the paper.
- **Forgetting to detach old policies.** The loss value can be correct while gradients flow into snapshots that should stay fixed. `test_snapshots_no_gradient` checks this independently of numerical reference comparisons.
- **Averaging all valid tokens together.** `m5_token_mean` implements a legitimate alternative aggregation, but violates this exercise's equal-response weighting. `test_response_duplication_invariance` duplicates tokens in just one response to distinguish the objectives. Problem **5** revisits weights for responses of different lengths.
